LoginFlow プライバシーポリシー

発効日: 2026年9月28日 / 最終更新: 2026年9月28日

LoginFlow はブラウザの拡張機能単体で動作するツールです。ユーザーが保存した情報は すべてユーザー自身の端末上の拡張機能ストレージ（Chrome の chrome.storage.local / chrome.storage.session、および 拡張機能ページの localStorage）に留まり、開発者を含む外部のサーバーへ 送信されることはありません。開発者はユーザーのデータを収集・閲覧・保存する手段を 持ちません。

1. 扱うデータと保存場所

LoginFlow は、ユーザーが登録した「サイトごとの自動入力フロー」に関する以下の情報を、 すべて端末上の拡張機能ストレージにのみ保存します。外部のサーバーには一切送信されません。

  • パスワード — AES-GCM（256bit）で暗号化して保存します。
  • 暗号化鍵（encryptionKey） — 上記パスワードの暗号化に使う鍵そのものも、 同じ拡張機能ストレージ内に保存されます（JWK形式）。
  • アカウントのラベル名、ログインID、記録した操作手順（クリック対象のCSS セレクタ、選択した値、クリックした要素のテキストの先頭50文字程度、条件判定や 待機に使うURL・パス部分を含む）— これらは暗号化されず平文で保存されます。
  • 自動入力フローの起点URL（オリジン＋パス）
  • 記録中の一時セッション（wizardSession: 開始URL・直前のURL・記録した操作一覧など）
  • 直近の実行時刻（lastExecutionTime）、実行ログ（いつ・どのサイトで・成功したか、 失敗した場合はどのステップで失敗したかを含め、直近100件まで）
  • （任意設定時のみ）WebAuthn の認証情報ID、生体認証の有効/無効設定と確認タイミング （biometricAuthEnabled / biometricTiming）
  • chrome.storage.session（ブラウザを閉じると消える一時領域）に保存する 短時間の実行状態（activeFlowSession、生体認証の確認済みフラグ biometricVerified）
  • 拡張機能のページ（オプション画面・デモページなど）が使う表示設定は、それらページの localStorage に保存されます（テーマ設定、初回案内を表示済みかのフラグ loginflow_warn_seen など）。いずれも表示上の好みの記録であり、認証情報は 含みません。

暗号化についての注意

パスワードの暗号化は、ストレージの中身をそのまま覗いても平文が読めないようにするための ものです。ただし暗号化に使う鍵は同じ端末の拡張機能ストレージ内に保存されているため、 その端末やChromeプロファイル自体にアクセスできる人（同一端末の他ユーザーや、 端末を物理的に操作できる人など）に対する保護効果はありません。あくまで 「ストレージの中身を偶然・直接見ても読めない」ことを目的とした設計です。

生体認証（WebAuthn）について

生体認証を有効にすると、保存済みの認証情報を自動入力で使う前に、指紋認証やPINなど 端末の認証を求める確認画面が挟まります。これは暗号化鍵を生成・保護する機能ではなく、 「使う前にもう一度本人確認を行う」ための実行前チェックです。確認結果は chrome.storage.sessionに一時的に記録され、ブラウザを閉じると消えます。

2. 外部送信・収集・販売・共有はありません

LoginFlow のコード内には、ユーザーデータを外部へ送信する処理（fetch、 XMLHttpRequest、sendBeacon、WebSocket など）は 一切実装されていません。アクセス解析（アナリティクス）やトラッキング、クラッシュレポートの 自動送信も行っていません。ユーザーデータの第三者への提供・共有・販売は行いません。

3. 権限とその理由

権限用途
storage登録したサイト情報・暗号化したパスワード・実行ログなどをローカルに保存するため
activeTabユーザーが拡張機能アイコンやショートカットを操作した際に今開いているタブへ自動入力を実行するため、および操作手順の記録（ウィザード）を開始したタブでスクリプトを動かすため
tabs読み込みが完了したタブのURLを端末内で保存済みサイトの一覧と照合し、保存済みだが未許可のサイトを開いたときにバッジ表示やポップアップで許可を促すため。このURLはどこにも保存・送信されません
scripting登録済みサイトや、操作手順を記録中のタブで自動入力・記録用のスクリプトを実行するため
downloadsバックアップファイル（パスフレーズで暗号化したJSON）を、ユーザーが選んだ保存先へ書き出すため
ホスト権限（http(s)://*/*、オプション権限）ユーザーがそのサイトで「操作を記録」を開始した時、自動入力トグルをオンにした時、またはポップアップで「許可」ボタンを押した時に1件ずつ要求される「オプトイン」方式です。トグルをオフにすると許可も取り消されます。既定では未許可で、許可したサイトでのみ自動入力が動作します

4. ユーザーによるコントロール

  • オプションページから、登録済みサイトの削除、実行ログの削除、バックアップの作成・復元ができます。
  • サイトごとの許可（ホスト権限）は自動入力トグルと連動してオン・オフでき、オフにすると当該サイトでの自動入力は動作しません。
  • 拡張機能をアンインストールすると、端末上の拡張機能ストレージ（保存サイト・暗号化されたパスワード・実行ログなどすべて）は削除されます。ただし、以前にバックアップとして書き出したファイルはディスク上にそのまま残るため、不要であればユーザー自身で削除してください。

5. 外部リンク

拡張機能の画面には、開発者への任意の寄付を受け付ける Ko-fi へのテキストリンク （https://ko-fi.com/tonofue）、 および開発者の X（旧Twitter）アカウントへのリンク （https://x.com/LoginFlow） が表示される場合があります。これらは通常のテキストリンクであり、画像バッジなどの 外部リソースを自動的に読み込むことはありません。リンクをクリックした場合にのみ、 ブラウザで該当サイトが新しいタブで開きます。拡張機能自体がユーザーデータをこれらの サイトへ送信することはありません。リンク先での操作にはそれぞれのサイトのプライバシー ポリシーが適用されます。

6. Chrome ウェブストアの Limited Use について

LoginFlow による情報の利用は、Chrome ウェブストアの 「ユーザーデータに関するポリシー（Limited Use要件を含む）」に準拠しています。 データは自動入力・マクロ機能を提供する目的にのみ利用され、広告や信用力評価を含め、 それ以外の目的での利用・第三者への提供は行いません。

LoginFlow Privacy Policy

Effective date: September 28, 2026 / Last updated: September 28, 2026

LoginFlow is a self-contained browser extension. Everything you save stays in extension storage on your own device (Chrome's chrome.storage.local and chrome.storage.session, plus the extension pages' own localStorage) and is never sent to any server operated by the developer or anyone else. The developer has no means to collect, view, or retain your data.

1. Data Handled and Where It Is Stored

LoginFlow stores the following information related to the per-site auto-fill "flows" you create, entirely in extension storage on your device. None of it is transmitted to any external server.

  • Passwords — stored encrypted with AES-GCM (256-bit).
  • The encryption key itself (encryptionKey) — used to encrypt/decrypt the password above — is stored (as a JWK) in the same extension storage.
  • Account labels, login IDs, and the recorded steps of a flow (CSS selectors of the elements involved, selected values, the first ~50 characters of clicked elements' text, and URLs including path used for flow conditions or wait targets) — these are stored unencrypted, in plain text.
  • The flow's trigger URL (origin + path).
  • A temporary recording session (wizardSession: the start URL, the most recent URL, and the list of recorded actions).
  • The last execution time per site (lastExecutionTime) and execution logs (when, which site, success or failure, and which step failed if any — the most recent 100 entries).
  • (Only if you opt in) a WebAuthn credential ID, and your biometric settings (biometricAuthEnabled / biometricTiming).
  • Short-lived runtime state kept in chrome.storage.session (cleared when the browser closes): activeFlowSession and a temporary biometricVerified flag.
  • Display preferences used by the extension's own pages (options page, demo page, etc.) are stored in those pages' localStorage — e.g. the selected theme and a flag recording whether the first-run notice has been dismissed (loginflow_warn_seen). These are display preferences only and contain no credentials.

A note on encryption

Password encryption prevents the stored value from being read as plain text if someone simply looks inside the storage. However, the key used for that encryption is stored in the same on-device extension storage, so this does not protect against someone who already has access to the device or Chrome profile itself (for example another user of the same machine, or anyone with physical access to it). It is designed to prevent casual or incidental exposure of the stored value, not to withstand a device-level attacker.

About WebAuthn (biometric confirmation)

Enabling biometric authentication adds a confirmation step — fingerprint, PIN, or other device authentication — before a saved credential is used to auto-fill a form. This is a pre-use confirmation gate, not a mechanism that generates, unlocks, or otherwise protects the encryption key. The result of that confirmation is recorded temporarily in chrome.storage.session and is cleared when the browser closes.

2. No Collection, Transmission, Sale, or Sharing

The extension's source code contains no code that transmits your data externally (no fetch, XMLHttpRequest, sendBeacon, or WebSocket calls). There is no analytics, tracking, or automatic crash reporting. Your data is never sold, shared, or disclosed to any third party.

3. Permissions and Why They Are Needed

PermissionPurpose
storageTo store your registered sites, the encrypted password, and execution logs locally
activeTabTo run the auto-fill flow on the tab you are currently viewing when you trigger it via the icon or a keyboard shortcut, and to run the recording script on the tab where you start the step-recording wizard
tabsTo compare a completed tab's URL, on-device, against your saved sites so the extension can badge the icon and open the popup to ask for permission when you open a saved site that is not yet permitted. This URL is never stored or sent anywhere
scriptingTo run the auto-fill script on sites you have registered, and the recording script on the tab where you start the wizard
downloadsTo let you export a backup file (a passphrase-encrypted JSON file) to a location you choose
Host permissions (http(s)://*/*, optional)Requested one site at a time — when you start recording on that site, turn on that site's auto-fill toggle, or press "Allow" in the popup. Turning the toggle off revokes the permission again. Denied by default; auto-fill only runs on sites you have explicitly permitted

4. Your Control

  • From the options page you can delete saved sites, clear execution logs, and create or restore backups.
  • Per-site host permissions are tied to that site's auto-fill toggle; turning it off disables auto-fill and revokes the permission for that site.
  • Uninstalling the extension deletes all on-device extension storage (saved sites, the encrypted password, execution logs, and everything else listed above). Backup files you previously exported remain on disk and are not deleted automatically — remove them yourself if you no longer need them.

5. External Links

The extension's UI may show a plain text link to Ko-fi for supporting the developer (https://ko-fi.com/tonofue), and a link to the developer's X (formerly Twitter) account (https://x.com/LoginFlow). These are ordinary text links; no image badge or other external resource is loaded automatically. The linked site only opens, in a new tab, if you click it. The extension itself never sends any of your data to these sites. Your use of those sites is governed by their own privacy policies.

6. Chrome Web Store Limited Use Disclosure

LoginFlow's use of information complies with the Chrome Web Store User Data Policy, including the Limited Use requirements. Data is used solely to provide the auto-fill/macro feature and is not used or transferred for any other purpose, including advertising or creditworthiness.
